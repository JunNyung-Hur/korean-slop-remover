# korean-slop-remover

AI로 글을 쓰다 보면 문법은 맞는데 읽자마자 "AI가 썼구나" 싶은 글이 자주 나옵니다. 굵은 한 줄 슬로건, "~하고 ~하고 ~하고" 같은 나열, 긴 하이픈, 번역투, 독자가 궁금하지도 않은 내부 동작 설명 같은 것들입니다.

이 스킬은 그런 글을 걷어내고, 사람이 그 자리에서 실제로 쓸 법한 한국어 글을 쓰도록 돕기 위해 만들었습니다. README나 공지, 릴리즈 노트를 쓸 때는 물론이고, 이슈 댓글이나 커밋 메시지, 화면 문구, 평소 대화 답변에도 같은 기준이 적용됩니다.

## 설치

Claude Code에서 플러그인으로 설치하시려면 아래 두 명령을 차례로 실행하시면 됩니다.

```
/plugin marketplace add JunNyung-Hur/korean-slop-remover
/plugin install korean-slop-remover@junnyung-hur
```

Codex, Cursor 같은 다른 에이전트에서도 쓰고 싶으시다면 터미널에서 아래 명령으로 설치하실 수 있습니다. 설치할 에이전트를 고르는 안내가 함께 나옵니다.

```
npx skills add JunNyung-Hur/korean-slop-remover
```

## 사용법

설치한 뒤에는 한국어 글을 쓰거나 다듬어 달라고 하면 자동으로 적용됩니다.

직접 부르고 싶으시면 "korean-slop-remover로 이 글 다듬어 줘"처럼 말씀하시면 됩니다.

## 수정 기준

이슈, PR, README, 블로그, 기고문, 뉴스는 구성과 말투가 서로 달라서 문서 종류별 기준을 [references/types](skills/korean-slop-remover/references/types/)에 따로 정리해 두었습니다. 이슈를 뺀 나머지는 아직 초안이라 쓰면서 계속 고쳐 나갈 예정입니다.

모든 종류에 공통으로 보는 기준은 크게 세 가지입니다.

1. 글의 관점과 구성: 시스템이 하는 일을 설명하는 대신 독자가 궁금한 것의 결론을 쓰고, 기능을 소개할 때는 어디서 무엇을 누르면 되는지까지 씁니다. 설명은 독자가 아는 것에서 출발해 문장으로 쌓고, 할 일과 절차는 목록으로 나눕니다. 독자가 당연하게 기대하는 말이나 독자가 아무것도 할 수 없는 경고는 뺍니다.
2. 말투와 목소리: 주어 없는 제품 카피 대신 글쓴이가 독자에게 직접 말하는 글로 씁니다. README에는 담백한 ~합니다체, 메신저에는 간결한 말투처럼 매체에 맞춥니다.
3. AI 문체 패턴: 긴 하이픈, 가운뎃점, 3단 나열, 대구 압축, 광고 형용사, 번역투, 습관적인 끝인사, 짧은 내용에 붙인 과한 소제목과 불릿, "~것"으로 끝나는 명사구 소제목, 개수부터 알리는 예고 문장, 짧게 끊는 영어식 문장 호흡 같은 것들을 찾아 고칩니다.

규칙을 기계적으로 적용하다 보면 오히려 극단적으로 반응하게 되는 과잉 교정 문제도 한 번 더 점검합니다.
