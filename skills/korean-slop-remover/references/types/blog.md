# 블로그

실제 교정 사례를 일부 반영했지만 아직 초안이다. 쓰다가 어색한 결과가 나오면 이 파일부터 고친다.

## 독자

글쓴이의 이야기를 따라 읽는 사람이다. 검색해서 들어온 경우가 많아서, 처음 몇 문단에서 자기 상황과 같은지 확인하고 계속 읽을지 정한다.

## 구성

정해진 틀보다 글쓴이가 겪은 순서를 따른다. 기술 블로그라면 보통 이렇게 흘러간다.

1. 어떤 상황이었는지
2. 무엇을 해 봤고 어디서 막혔는지
3. 결국 어떻게 해결했는지
4. 다음에 비슷한 일을 겪을 사람에게 남길 말

화면이나 결과를 보여 줄 때는 사진을 먼저 두고 바로 아래에서 설명한다.

## 말투

글쓴이의 목소리로 쓴다. ~습니다체나 ~다체 중 하나를 골라 끝까지 맞춘다. "저는", "제가"를 써도 된다.

## 제목, 굵은 글씨, 그림

- 소제목은 이야기가 바뀌는 곳에만 단다. 관례적으로 "문제 상황", "원인", "해결"처럼 쓴다.
- 굵은 글씨는 거의 쓰지 않는다.
- 사진과 스크린샷은 자주 써도 된다. 사진마다 바로 아래에 그 사진에서 무엇을 보면 되는지 쓴다.

## 자주 나오는 슬롭

- "오늘은 ~에 대해 알아보겠습니다"로 시작한다.
- 겪은 이야기 없이 개념 설명으로 채운다.
- "결론적으로"로 앞의 내용을 다시 요약한다.
- "도움이 되셨길 바랍니다"로 끝낸다.

## 예시

> 지난주에 배포하고 나서 업로드가 간헐적으로 실패한다는 문의가 들어왔습니다. 로그를 보니 실패한 요청은 모두 nginx에서 413을 받고 있었는데, 정작 파일 크기는 제한보다 한참 작았습니다.
>
> 처음에는 nginx 설정이 배포 때 덮어써진 줄 알았습니다. 그런데 설정 파일은 그대로였고, 같은 파일을 다시 올리면 성공하기도 했습니다.
